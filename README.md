# Расследование регрессии в отчёте (v1.0 → v1.1)

## В чём проявлялась проблема

В версии **v1.0** отчёт (`python project/report.py`) содержал **170 записей**,
а после обновления до **v1.1** - только **160**. Требования к составу отчёта
при этом не менялись, исходные данные (`data.json`) тоже.

## После какого изменения она появилась

Прошёл по истории коммитов между `release: v1.0 stable report` и `release: v1.1`
и посмотрел изменения в `project/report.py` и `project/config.json`.

- `feat: add configurable report ordering` - добавлена сортировка (`sort_by`, `descending`),
  состав отчёта не меняет, всё ещё 170 записей.
- **`feat: add progress limit`** - появилась функция `should_include()` и параметр
  `max_progress: 100` в `config.json`. **После этого коммита записей стало 160.**
- Остальные коммиты (документация, helpers, metadata, labels, timestamps и т. д.)
  логику фильтрации не затрагивают.

## В чём заключалась причина

В `should_include()` проверка лимита была написана так:

```python
if value is not None and record["progress"] >= value:
    return False
```

Параметр называется `max_progress`, то есть это **максимально допустимое значение
включительно**. Но оператор `>=` отбрасывает и записи, у которых `progress` **ровно равен**
лимиту. В данных 10 записей с `progress = 100` (завершённые задачи), а в конфиге по
умолчанию `max_progress = 100`, поэтому они выпали из отчёта: 170 − 10 = 160.

## Какое исправление внесено

Строгое сравнение вместо нестрогого в `project/report.py`:

```diff
-        and record["progress"] >= value
+        and record["progress"] > value
```

Теперь исключаются только записи, у которых `progress` **больше** лимита.

## Почему возможности v1.1 сохранились

- Функция `should_include()` и параметр `max_progress` остались: фильтр по лимиту
  работает, просто с правильной (включительной) границей.
- Настраиваемая сортировка (`sort_by`, `descending`) не тронута.
- `data.json`, `config.json`, `VERSION` (1.1), документация и остальные файлы
  новой версии не изменены. Проект не откатывался к v1.0, исправлена одна строка.
