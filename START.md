# Практика. Регрессия: вчера работало, а сегодня упало

В этой работе вам предстоит исследовать историю небольшого проекта и восстановить поведение, которое изменилось между версиями.

## Начало работы

1. Создайте новую рабочую ветку.
2. Дождитесь завершения автоматической подготовки задания в разделе **CI/CD**.
3. После завершения генерации в вашей ветке появится файл `TASK.md`.
4. Прочитайте `TASK.md` и приступайте к расследованию.

## Что понадобится

Используйте возможности GitVerse для исследования проекта:

- историю коммитов;
- изменения внутри отдельных коммитов;
- сравнение версий файлов;
- историю изменения проекта.

Изучайте не только текущее состояние файлов, но и то, **как проект пришёл к нему**.

Ваша задача — не просто добиться правильного результата, а разобраться, **после какого изменения возникла регрессия и почему**.

## После исправления

В корне вашей ветке добавьте `README.md` с кратким описанием проведённого расследования.

Укажите:

- в чём проявлялась проблема;
- после какого изменения она появилась;
- в чём заключалась причина;
- какое исправление вы внесли;
- почему после исправления сохранились возможности актуальной версии проекта.


## Проверка

Когда считаете, что проблема исправлена:

1. откройте раздел **CI/CD**;
2. запустите вручную workflow **Practice 2 — Checker** для своей рабочей ветки;
3. изучите результат проверки;
4. при необходимости продолжите расследование и повторите проверку.

После успешного прохождения Checker создайте **Pull Request** с выполненной работой.

## Важно

Простой возврат проекта к старой версии не является решением.

Исправление должно восстановить ожидаемое поведение проекта и сохранить полезные возможности актуальной версии.

Не изменяйте исходные данные только ради прохождения автоматической проверки.

У разных студентов могут отличаться данные, история проекта и причина регрессии.
